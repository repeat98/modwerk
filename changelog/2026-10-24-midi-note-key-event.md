Octatrack base (USB, beta): three new take events for MIDI tracks. `ev_midi_note_key` sits at the point where a MIDI track's note (from its trig, chord or arpeggiator) is about to be corrected to the track's KEY and sent. A module that takes it can rewrite the note or drop it, for its own scales or a scale that changes per step; stock still sends every note-off for the note it sent. It runs in the MIDI sequencer's interrupt, once per note. `ev_arp_setup_knob` sits where an encoder turns on MIDI ARP SETUP (LEN, KEY or an arp note), so a module can take one turn, such as KEY while a trig is held, and leave the rest to stock; stock itself ignores a held trig there and edits the track's KEY. `ev_arp_setup_text` sits where ARP SETUP draws LEN or KEY, so a module can show its own text there (a held step's KEY, for one) through stock's own drawing. With no module taking them, both behave as stock. No module uses them yet; upstream octabam's MIDI Scales patches both places, so a port of it would take these events instead. The beta base becomes `9542efef…` (its USB Audio variants with it); the base-bound packages only follow the new base. On the adapted ColdFire emulator (stock 1.40C, a copied project, MIDI track 1 arpeggiating a chord), the new base sent the same MIDI bytes as stock and the previous base with KEY off, C Major and F Minor, and a test record poked into the event's row turned every note into C with no note left hanging. Holding a trig and turning knobs in grid recording (NOTE, ARP and ARP SETUP pages) stored the same locks and the same KEY as stock, and a record that returns at once on `ev_arp_setup_knob` left KEY unchanged. On a contributor's MKII, the same change on base `92a13ff0…` (main through #924) passed the self-test and KEY played the right notes; `9542efef…` itself ran on the emulator only. The base README now says how to build the base in the repository's toolchain image on Linux, and the module guide how a take event's site and tail are written.
