Octatrack base 0.8.2: a Keep can no longer be lost to an older saved set after a start at which the card could not be read. When the Octatrack could not read either saved-set file at startup, it said nothing was saved, and the next Keep could be numbered lower than the set already on the card, so once the card read normally again, the older set came back at startup instead of the new one. The base now tells a missing file from one it could not read. A start that could not read the saved modules says so (Status: "The saved modules couldn't be read"). A Keep after such a start is written over every file the unit could not read before Status shows "Saved and checked", so what those files held can never come back over it.
