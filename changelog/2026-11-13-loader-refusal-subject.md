Octatrack over USB: a refusal now names what it met. When the Octatrack turns a module down as a conflict, the base records the cause where the check fails: a part of the base it needs and this base lacks, stock code another module already patches, or DSP memory another module already holds, with that module. The site then says which one it was and names the other module, instead of one text for all three, and `npm run device` prints the feature bits, the site address or the DSP word with the module's name. A base built before this keeps the earlier text; the base gets the new read-out with its next build.

Octatrack SDK: the loader's `modwerk_runtime_refused_subject()` and the base's vendor request 41 report the subject (MWRF v1, 16 bytes) beside the refusal code, and `sdk/runtime/loader-refusals.json` lists the subjects with their words, held to `loader.h` by the same test as the codes.
