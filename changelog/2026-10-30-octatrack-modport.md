Octatrack: `scripts/octatrack-modport.py` turns a ProTracker module (.mod, 4, 6 or 8 channels) into an Octatrack project, written as a copy of an empty project the unit made. Each channel becomes a Flex track, each song position a pattern with the module's notes as trigs and sample, pitch, volume and sample-offset locks, each sample a WAV in the project's own folder, and the tempo comes from the song's speed and BPM. `--report` lists what would be converted and what is left out (slides, vibrato, arpeggio and other effects) without writing anything. `--sliced` puts every sample into one WAV in Flex slot 1 instead, with one slice per sample in the project's markers file, slice mode on for every track and each trig locking STRT to its sample's slice (pitch stays per sample; 9xx offsets are then left out). `--arranger` also writes the song order into arrangement 1 (arr01), one row per song position with identical consecutive patterns folded into repeats; it edits the template's own arrangement file in place and refuses one it does not recognise. Both are off by default and verified on synthetic and reference files. The developer reports that MODPORT's projects run on their own Octatrack MKI (31 Oct 2026); which options and which revision were tried was not recorded. The markers layout follows octapy (MIT) and the arrangement layout ot-tools-io by Mike Robeson (AGPL-3.0-or-later), each checked against ot-tools-io's unit-saved test files; no code was copied from either.
