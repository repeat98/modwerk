Pull requests: editing a description no longer reruns and cancels every check, and one catalogue or evidence problem shows as one red job. From 20 to 21 November, 145 of 400 PR check runs repeated a commit that had already run, and 55 of 79 cancelled runs were cancelled by such a repeat, mostly description edits. The description check now runs in its own workflow (`pr-description.yml`) on every push, edit and draft change; `module-pr.yml` no longer runs on edits. The suites, the Windows paths and `octatrack-source` now wait for `module-contract`, which already reports a stale catalogue, missing captures or approval; before, one such problem turned six jobs red. The author release path checks the exact description it merges itself. Checked with the workflow tests in `scripts/pr-body.test.mjs` and `npm run pr:ready`.
