Improvement: Octatrack base (USB, beta): a power cut or USB dropout during a base update no longer leaves the Octatrack unable to start. Until now the base kept one copy of itself in the Octatrack's flash and rewrote it in place: a power cut during those seconds left nothing to start, short of the startup menu's MIDI recovery with a DIN MIDI interface. The base now keeps two copies (slots) behind a small boot stub of our own, which Elektron's bootloader starts in place of the OS. An update writes only the slot the unit can lose, its record last, so whatever happens meanwhile, the stub still finds a whole base to start. An update restarts the Octatrack once at most: on a unit with the two slots, the running base saves the new one into its spare slot under Elektron's own upgrade screen (PREPARING FLASH, WRITING OS DATA, VERIFYING OS DATA) and restarts into it; otherwise the new base starts first and then saves itself while it keeps running, showing BASE UPDATE with a progress bar and BASE SAVED. The stub starts the newest base. If that base fails to start twice before it has run for 15 seconds (and, when another base wrote it, before a computer has talked to it over USB), the stub goes back to the previous one; the unit shows UPDATE UNDONE and the site says so. A new base shows BASE UPDATED at its first start. Nothing writes below Elektron's bootloader, so FUNC at power-on (MIDI UPGRADE) stays the recovery of last resort. A unit installed from the card switches to the two slots on its first USB update. Its current base is copied first, so it is the fallback for that update too. Writing the stub's own sector, under a second once per unit, is the one moment a power cut can still need the startup menu. Checked: host tests cut the power after every one of an update's 283 flash operations, and a base starts after each; for the switch to two slots, only the cuts inside the stub's sector fail. The stub ran in an emulator with Elektron's own bootloader code (its last steps and its unpacker) for six slot states, entering the OS exactly as the bootloader does. Not yet run on a unit: the stub's first real start, stock's upgrade screen called by the base, the confirm and the switch need the owner's hardware run, with a DIN MIDI interface at hand, before release.
