Pull requests: a PR now merges only when its checks are green, and contributor PRs stop conflicting on the changelog. On 23 October #805 (Play Start) was merged seconds after its checks started; they failed a minute later, and every push to `main` failed to deploy until #809 moved the module to `sdk/drafts/`. Since 19 October three of five red spells on `main` came from PRs merged before their checks finished. The PR checks now end in one `module-pr-ok` job that passes only when every other check passed or was skipped by scope, for the `main` ruleset to require with auto-merge. Application changelog entries are now one file each under `changelog/` (`npm run changelog` prints them all); `CHANGELOG.md` keeps the history up to 22 October and the check refuses new entries in it. `npm run check` reports every catalogue, licence and changelog failure of a stage together, so #805 would have shown its missing evidence and its stray changelog file in one run. `modules:check` tells an unlisted, unqualified module to move to `sdk/drafts/`. The release approval lookup retries a GitHub 5xx or dropped connection three times instead of failing the deploy (#790 and #792 failed that way on 22 October). Checked with unit tests for the changelog files and the retry, and with `npm run check`; the required check takes effect once the ruleset names it.
