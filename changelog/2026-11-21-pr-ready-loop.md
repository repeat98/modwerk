Pull requests: `pr:ready` stops restarting on tests that only failed under load, and on `main` moving. In the Grain #1858 release on 21 November, 28 `pr:ready` runs of 10 to 16 minutes ended "Not ready" on 5-second test timeouts while other sessions' checks loaded the computer (load average above 100), or on "Your branch does not contain current main" after main moved. A Vitest file that fails in the full run is now rerun alone on one worker. If it passes there, the check passes and lists it as flaky; if it fails again, or more than 12 files failed, the check fails as before. On a clean branch, `pr:ready` now merges current main itself. On a conflict it aborts the merge, leaving the branch as it was, and names the files. A main that moves during the run needs no second run, because the PR's CI checks the merge with the newest main. Checked with new cases in `src/tooling/check.test.ts` (passes alone, fails again) and `scripts/pr-ready.test.mjs` (clean merge, aborted conflict), and `npm run pr:ready`.
