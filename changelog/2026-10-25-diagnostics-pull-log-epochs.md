Diagnostics pull (the owner's `npm run diagnostics:pull`): when a base update restarts the Octatrack's own log at start 1, the summary no longer mixes the old log into the new one. Before, the old log's incidents kept their start and number, so they printed among the new base's (as its "start 3", for example) and the restart count was off. Each log is now kept apart: restarts are counted per log, and an earlier log's lines name the base they ran on. A DSP stall after a session that ended stopped at 95 % CPU or more after a PROJ … RIGHT YES key walk, with nothing installed, is now marked "likely an OS upgrade or USB disk mode". That is a hint, not a cause. Checked with unit tests and against the latest pull. Limit: a log piece that failed to upload and comes again later from another browser is read as a new log.
