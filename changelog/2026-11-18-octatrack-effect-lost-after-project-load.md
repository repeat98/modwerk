Fix: Octatrack base 0.7.9 keeps a module effect on its track across a power cycle when a project was loaded while the module was installed. Loading a project replaced the base's effect map with that project's lines, so an installed module the project did not name yet stayed on its handle unnamed. Once a track used it and the project was saved, the file had no line for it. At the next start a module tied to its handle (Tape Echo, BBD Delay, Euclid) was refused NO ROOM FOR IT, both by the restore and by every try to add it again. The base now names every module that stays on its handle after a load, so the save keeps it. Projects saved before this fix lack the line: the base now gives such a handle to the module the catalogue puts there, the one the MISSING page already named. Reproduced and fixed in a host test (`test_dsp.c`); the shared diagnostics of four units show the refusal. Not yet tried on a unit.
