Developer tools: `npm run device -- boot` no longer RAM-boots over a base update that is flashed but not yet confirmed. Each restart, a RAM boot included, spends one of the update's two starts, and with both spent the Octatrack went back to its previous base. The command now waits for the update to confirm itself when the unit is running it, and otherwise refuses with the steps to confirm it first (`--spend-tries` boots anyway).
