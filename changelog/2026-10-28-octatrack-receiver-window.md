Octatrack base (beta): each DSP core has about 450 more words of room for effect code (4,741 and 4,867 words with nothing placed, were 4,292 and 4,418). The loader's packet handling, which runs only when code is being sent, now runs from the DSPs' shared memory instead of the effect area. Code there runs at half speed, so only that part moved; effects still run from the faster memory. A Part with eight heavy stock effects on one group of tracks now loads (finding 53: LO-FI, FILTER, DJ EQUALIZER and CHORUS with DARK REV, SPRING REV, PLATE REV and FLANGER on tracks 5-8). One new limit: Air Chorus and BBD each fill a whole FX2 buffer, so at most two of tracks 1-4, and two of tracks 5-8, run them on FX2 at once (were three); a third shows NO ROOM. Stock effects, E-Verb and Mini Verb are not affected.

Swapping one FX2 effect for another on a track no longer fails with "MEMORY FULL ... NEEDS A BUFFER" when the four tracks of that DSP core already run reverbs, delays or other effects with delay memory: the new effect takes over the old one's memory, as on the stock OS. Where an effect still cannot get room, the message now says so plainly: "NO ROOM", the effect, "FX2 ON T1-4 FULL", "CHANGE ONE FIRST".

Developer tools: `npm run device -- meter 0|1` reads the DSP load meter again (it asked for a report length current bases refuse).
