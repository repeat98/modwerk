Fix: Octatrack (USB, beta): after a base update the site now puts your modules back. Each Modwerk base loads at startup only the module set that it saved itself. A set saved by another base is skipped, because some packages (Sidechain Compressor, Output Matrix, Analog BD, CC Map, Recorder Loop Fix) are linked to the base that saved them. So every base update, over USB or from the card, and every power cycle back to an older flashed base left the Octatrack running without modules. Beta testers' shared diagnostics show this after base updates on 20–24 October: 14, 12, 11 and 3 modules were gone at the next start. The update dialog even said the modules stay. Now, when the Octatrack reports that the set on its card came from another base and nothing loaded, the site opens the usual sync for the modules this browser last saw on it. You review it, the unit runs its self-test, and you keep it or undo it. It uses a module set with exactly those modules, or saves them as a new set named "From my Octatrack". The sync opens once per base. The Status page now says "Saved by another base, so not loaded" instead of "Nothing saved on it yet". Limits: this works only in a browser that read the unit before the change; the base itself still skips another base's set. The set's USB Audio layout and the unit's stock-effect choices from before the first read after this update are not remembered. Checked with unit and component tests; not yet tried in a browser or on a unit.
