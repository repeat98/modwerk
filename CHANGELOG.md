# Application changelog

## 15 October 2026

- Fixed `npm run module:doctor` and `npm run modules:compat` failing on Windows with a `UnicodeDecodeError`: the cross-compatibility gate now reads the repository's JSON and source files as UTF-8 instead of the Windows code page. Nothing changes on macOS and Linux. `npm run modules:pairs` (part of `npm run check`) still stops on Windows because octabam's pinned tools read files the same way and use `\` in paths; that is not fixed here.

## 14 October 2026

- Card-builder compatibility now grows with the square of the number of Octatrack modules instead of doubling with each one. `npm run modules:pairs` runs octabam's ledger on every module alone and in every pair, in each context POLY8's shared machine list creates, and writes a 13 KB `src/catalog/compatibility-pairs.json`. It replaces 585,455 recorded selections (68 MB in `native-metadata.json`, 4.8 MB shipped to the site) and the 30-module ceiling of their bit masks. The same check proves with the full ledger that pairs decide every larger selection: it found all 585,327 recorded composed selections clean and agreed with the full ledger on 6,000 further selections, including every one of 20 modules or more. The configurator derives its refusals from refused pairs, replacing the hand-written VECTOR, Analog BD and FM Synth rules and POLY8's exception list, and honours every module's flagged conflicts, except two stale flags that Sidechain Compressor and TapeHead keep until their next versions. A pair the ledger refuses that neither module flags now fails the check ([flag every incompatibility](docs/module-guides/README.md#flag-every-incompatibility)). Limits: USB sets still refuse every byte collision, and the ledger proves declarations, not DSP placement, cycles or hardware behaviour.
- Fixed Digitakt and Digitone module cards showing no artwork for Sequencer and MIDI modules (Euclidean Sequencing, MIDI Retrig, Per-step Note Accumulator, CC Assignment Names). The card drew a generic picture for the module's family and had none for "Sequencer" or "MIDI", so those cards stayed empty. Cards, module pages and build summaries now show each module's own saved `media/thumbnail.svg`, so the displayed art and the saved file are the same drawing. The older modules' saved thumbnails match what their cards drew before, so those look unchanged. Checked by rendering every Digitakt card's real markup with the site stylesheet in headless Chrome; not checked on the live site, in Firefox or Safari, or on the module page and build summary.
- Mitigated the whole screen going dark when you opened the configuration page. Its compatibility panel, stock FX summary and (for beta members) Octatrack page download only when you open it, and when one did not arrive, because the connection dropped or a newer release had replaced it while the tab was open, nothing caught the failure and React removed the entire page. A part that fails to load now shows a short notice in its place and the rest of the page, including firmware and build, keeps working. Any other page that fails to render shows what went wrong with a Reload button and a link back to the library, keeps the sidebar, and recovers when you open another page; a fault in the app shell itself shows the same message instead of an empty screen. A part that did not arrive still needs a reload to load, and faults inside click handlers or background requests are not covered. Cause inferred from the code and reproduced only as far as an uncaught failed import in a test, not on the deployed site.
- Stopped shared engine changes from failing every pull request on Tape Echo's retained evidence. A module that keeps an earlier version's evidence now has its own folder and its own package rows in `src/engine/assets` compared, not all shared runtime, platform and build code; like every other module, it relies on the app's tests and native matrices for shared code. The Tape Echo browser-preservation and builder-preservation bindings, their parity runner, generator and records are removed ([qualification](docs/MODULE_QUALIFICATION.md)).
- Every member's Octatrack card builds now play the docking startup, not only beta testers'. It ends on the mark and MODWERK, without the NEW / BETA labels or the shockwave's outline and dotted echo. The mark flies in faster (landed by 0.89 s instead of 1.27 s), the shockwave bends the screen longer (0.58 s instead of 0.42 s), and MODWERK stands for about 1.2 s instead of 0.9 s; the startup still lasts 3.5 s. A configuration can keep the classic startup (**Startup** on the configuration page), and a selection that composes only without the docking hooks keeps it automatically, with a note in the build panel. The startup no longer depends on beta membership; beta modules still do. The startup package is 3.0.0, rebuilt with the pinned toolchain; its native and emulator checks pass on MKI and MKII, and the exact core-only build was RAM-booted once on an MKII, where the owner reported it worked. Not tried on hardware: the classic startup, an MKI, a flashed install and a power-cycle with a project loaded ([release record](docs/STARTUP_ANIMATION.md#release-gate)). The Elekloader base's own startup is unchanged.
- Mitigated community features (session, catalog, people online, announcements, forum) staying empty in Firefox until the page was reloaded several times, when requests to the community API got no answer. Firefox reports those requests as “CORS request did not succeed” with a null status; that is a missing response, not a missing CORS header. A community read still unanswered after five seconds now gets one fresh request beside it, as a reload would; the first answer wins and the other is cancelled, so a read that never answers gives up after 35 seconds instead of 60. When reads reach the service again after an outage, the session, developer session, catalog, people online, public announcement, notification count, module statistics and the forum's thread list, highlights, topics and recent replies reload without a page reload. Writes are still never sent twice. Why these requests sometimes get no answer (network path, browser or Worker) is not established; this change was tested with simulated stalls and outages, not in a live Firefox session.
- Added an automatic cross-compatibility gate for Octatrack modules (`npm run modules:compat`, part of `npm run check` and `npm run module:doctor`, so registered authors' automatic updates pass it too). It reads declarations only (octabam's claim model, the integration's port recipes when present, the committed base package; no firmware, no emulator) and checks every pair of active modules, the whole set and the base for overlapping patched bytes, stock copies taken from bytes another owner patches, shared tables, effect IDs and octabam's DSP resource rules. Shared behaviour is moving to Elekloader-style events: a raw patch on an event's stock site fails and points to subscribing, and two behaviour hooks meeting on a new site are told to request an event. Today's intended overlaps are listed with reasons in `sdk/machines/octatrack/compatibility.json`: the POLY8-owned machine group (POLY8, VECTOR, FM Synth, Scale Quantizer, Analog BD) and Repitch/POLY8 and Mute Modes/POLY8 as pending migration to their planned events. Any new overlap, or a stale entry, fails with the modules, the byte range and the fix. The event registry is a two-site fixture until `sdk/machines/octatrack/events.json` lands; the gate does not prove runtime behaviour, DSP placement or hardware compatibility.
