# Analog Rytm MKII: the base's lean engine — 21 November 2026

The Modwerk base with the lean engine (`base/perf-*`, `common` in `base.json`) in every variant, as this branch vendors it: send-bus **20fbc98f**, voices **ee44bde6**, plain **5ca4480f** (`sdk/machines/analog-rytm-mkii/base-binding.json`), built by `npm run machine:base -- analog-rytm-mkii` with the reviewed toolchain. The runs below used source `6ab2b2d12` (send-bus `3cb27253`, voices `aba85f2c`, plain `ae77e1b0`); `7e667bbaa` then made the CPU and OVR marks blink, which changes only the mark's tick and draw (168 B of `.run` and up to 4 B of `.bss` in each variant). The code is the retired Improved Performance module's (#1937, 0.2.0 on #1941, retired in #1944), with its constants prefixed `LE_` and its globals `le_`; the renames leave every variant's code sections and relocations unchanged.

- **Emulator** (rytm-emu with a cache model and zero-time interrupt, the author's local copy): each variant alone on stock OS 1.74 (LB01 plain, LS01 send-bus, LV01 voices, linked with `scripts/link-image.mjs` from the packages before the renames), against the same image with the 19 lean-engine sites put back to stock. Parameter words, smoother states, control frames, voice records, voice gains and the DAC output were identical in every block (plain 69,552, send-bus 69,537, voices 69,552). The interrupt ran about 31,100 fewer instructions a block (47 %).
- **On a unit:** Nathaniel Pavel (@npp1993), Analog Rytm MKII, OS 1.74, development image **LD01** (image `fafa9122…`, CRC `aa497278`; the voices variant as a development base `a4564012` beside 17 modules, storage layout `0x71088503`), RAM-booted over the link, hands off, on the project then loaded (KIT 1, 120 BPM, pattern A01):
  - **Load** (the core's `core_audio_load`, 240 reads over 60 s of play): LD01 79.2 % playing, 48.8 % stopped before the first play. On the same pattern and session, the same set without the lean engine (CM02) read 85.8 % and 76.7 %, and the module build IQ07 79.4 % and 51.5 %.
  - **Wake-up:** 10 cycles of STOP, 15 s rest, PLAY: no fault, the link armed throughout; in the first 3 s after PLAY the load read at most 81.6 % (61 reads, one in about 73 blocks, so a single slow block can be missed), against 79.2 % steady. No CPU or OVR mark at the screenshot 3 s after PLAY.
  - **Soak:** 30 minutes of play with a STOP, 10 s rest and PLAY every 5 minutes: 57 checks, every one armed, the same image, playing; load mean 79.2 %, highest read 82.0 %.
  - **Finding:** after the first play, the stopped load stayed at about 77 % for at least 90 s (CM02's stopped level): on this project the parts do not come back to rest after playing. The sound is stock's either way; the cause is not found yet (a counting build would show which part stays busy).
  - **Hands on** (as the tester reported): live recording while playing, kit and project loads with sound ringing, the delay and reverb tails dying away and coming back on the next hit: all normal. Playing by hand did not bring up the CPU or OVR mark.
  - **USB audio** (Overbridge, the Mac's 12-in, 12-out "Analog Rytm" device at 48 kHz): about 6 minutes of a −30 dBFS 440 Hz tone sent on all 12 channels to the unit while the tester played a heavier pattern and changed it by hand (so the phases are not a clean comparison). Load mean 84.9 % (max read 87.9 %) before streaming, 91.5 % (max 95.7 %) while streaming, and 79.5 % once streaming ended. The link stayed armed with the same image throughout. The OVR mark showed while streaming, and the tester heard clean audio at the unit. Captures of the unit's USB output with sox (15 and 20 s, every sample there, the 12 channels distinct) sounded clean to the tester. A capture with ffmpeg's AVFoundation input came out short and choppy, but that is the recorder: it lost about a tenth of the samples from the Mac's own microphone too.
  - **Blinking marks** (LB02, image CRC `9883fc99`, the same set on the blinking source with the test switch `CW_TEST_CYCLE=8`, which steps the mark through none, CPU and OVR every 4 s whatever the load): 160 screenshots over the link on the BD page. Five corner states, all as intended: the voice type name with no mark, CPU and the empty bar in turn, OVR as lit text in a dark box (columns 110 to 127) and as dark text on the lit bar in turn. The rest of the screen was unchanged.
- **Not run yet:** the CPU mark alone at its threshold, a flashed release image, the send-bus and plain variants on a unit, a second unit, USB streaming on the same pattern without the lean engine.
