# Analog Rytm MKII: MIDI Engine in the library — 3 November 2026

svindler's MIDI Engine 0.1.0-experimental (#1152) comes into `modules/midi-engine`, as #1170 now asks of a new module, with its release notes and its source-only OS 1.74 package pinned in `sdk/imports/elekloader-midi-engine-2026-11-03.json` (commit `a4929e7f`). It claims `machine:42`, the hidden machine slot its kits store, as the owner asked on #1152. Downloads stay off (`DIGI_DOWNLOADS_ENABLED`).

- **Build:** `scripts/build-elemod-isolated.sh` in `modwerk-source-tools` (`43ae649e…`, GCC 16.2.0) from `8f83e26f`. The export reproduces with `package-elemod-recipe.mjs --check`, and `verify-elemod-release-exports.mjs` reproduces all 32 committed exports from the same build.
- **Package:** `8797a971…3f911`.
- **Linking together:** `checkLinkable` on the developer's own stock OS 1.74 main image, stock-byte guards included: core-ar2 0.7, Filter Hz 1.2.0, Loop Sync 0.2.0, Pipo Loop 0.1.1, Sample RATE 0.1.0, Silent Pad+Trig Settings 0.6.0 and MIDI Engine all at once report no problem; MIDI Engine given twice reports 16. `planBuild` plans it with core-ar2 0.7 (`src/engine/elekloader/digi-build.test.ts`).
- **Built from the package:** the vendored kit's `build` on the developer's stock OS 1.74 file with core-ar2 0.7 and this package (build MER1): sections 1, 2, 5 and 8 byte for byte, 6 and 3 bits of sound storage. In rytm-emu it boots, takes a simulated Transfer upgrade from stock 1.74 and boots it from flash; leaving the MIDI machine and coming back, then PLAY, sends the same MIDI bytes as the unit-tested ME17 build.
- **On a unit:** builds ME09 to ME17 on the author's unit, as TESTING.md records. These were local GCC 12.2 builds of the same C. MER1, built from this package, ran on the same unit on 2026-11-17 over DIN: PLAY sent the lanes, PB, MW, AT and chords as ME17 did, leaving the machine and coming back switched the lanes OFF as on ME17, and no CC 64 went out (TESTING.md has the detail).
