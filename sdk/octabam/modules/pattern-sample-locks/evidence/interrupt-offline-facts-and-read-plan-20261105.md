## What existing read paths can observe

The private reconstruction's source-defined `REPORT` request is read-only and samples counters plus the frame-chain state, frame busy flag, INTC0 IPRL/IMRL, EPORT pin/edge flags, DSP select and eDMA status. The fields are read sequentially, so the values are a time-skewed snapshot; the report does not expose ICR priorities, INTC1 configuration, VBR, SR/A7/SSP/USP/TCB, SDRAM timing registers or clock-source state. Its `MEM` request is read-only but restricted to enumerated RAM ranges; peripheral registers are outside those ranges. The developer `profile`, `stats`, `guard` and memory interfaces are tied to a matching development build and are not raw chip-cycle or worst-case proofs.

The repository's restricted remote read-only session permits IDENTIFY, CAPABILITIES, RESULT, MISSING, INVENTORY, LOAD, LOG, the existing self-test record and fixed HELLO only; it explicitly excludes memory, keys, screen reads, trial, Keep, Undo and self-test start ([MCP session contract](../../../../docs/FRONTEND_MCP.md)). A stock OS exposes USB mass storage only and has no Modwerk vendor interface; even a public Modwerk base can return only fields it implements ([Octatrack driving guide](../../../../docs/OCTATRACK_DRIVING.md)). Thus public read scope can bind configuration/capability/inventory/load/log records where supported, but it cannot close the raw stack, ICR, clock or SDRAM questions. The reported physical IDENTIFY value is configuration SHA `9680…`, not a physical MAIN hash. The private reconstruction's MAIN hash is `877a…`; no physical image hash is available for comparison. The proof metadata do not establish that the physical image differs from the reconstruction. Any rebuilt diagnostic twin with changed inputs is a distinct evidence subject unless its complete image and configuration identity match exactly.

## Conditional, safety-scoped observation plan

This is a proposal only. Before any unit session, the owner/tester must explicitly select the unit, time window, permitted base and read operations, and confirm the current IDENTIFY configuration SHA and complete module inventory. No permission for RAM boot, candidate installation, panel input, Keep, project save, flash or power cycle is implied here.

1. **Read-only baseline, if the currently running base supports it:** record model/OS, base configuration identity, capabilities, active digest, complete inventory, LOAD/status and existing LOG/self-test record. Record the project/Part as left untouched. On stock OS or any base that does not answer a field, stop and mark it unavailable; do not change firmware to gain access.
2. **Only if separately authorized, use a named RAM-only diagnostic twin:** bind its builder inputs, configuration SHA, complete image SHA, package SHA-256 and source fingerprint before loading. A twin with extra diagnostics or different cache, DSP, USB or module settings has a different configuration identity; its measurements cannot be attributed to the physical unit reporting `9680…`. The private proof metadata alone do not classify that physical unit as a development build. Read the existing development `REPORT` fields, profile/guard/load, and only the permitted RAM ranges. Do not issue write-capable vendor requests or manipulate hardware inputs to force level-seven/eDMA events.
3. **Capture specific state only through an existing reviewed read path:** current VBR; SR mode and IPL; A7/SSP/USP, current task/TCB and stack bounds/high-water; INTC0/1 ICR, IMR and pending state; EPORT routing, edge configuration and flags; timer/PLL/core/bus-clock configuration; SDRAM controller timing/refresh and arbitration; cache control/alias state. The existing public session and REPORT do not provide all these values. Where a field has no existing read-only interface, this plan requires an owner-reviewed diagnostic mechanism/build and a new image identity; do not probe it through unrestricted memory reads.
4. **If a separately approved RAM-only candidate trial is eventually needed:** first snapshot exact IDENTIFY configuration SHA, active digest and complete inventory; use the exact candidate package hash; use a timed trial/Undo path rather than the session's immediate-accept `try`; do not Keep. After Undo, verify the same IDENTIFY configuration SHA, baseline active digest and every inventory entry. If Undo is ambiguous or these differ, stop and hand recovery to the owner; do not power-cycle. A project save, flash and power cycle each require separate explicit authorization and are outside this plan.

Repeated profile, guard, timer or status samples can report maxima observed during that run and characterize tested conditions. They do not prove worst case: no finite sampling duration excludes rarer interrupts, edge retrigger, companion callbacks, cache misses, SDRAM contention or untested stack paths. The static instruction counts and timer measurements must remain separately labelled; neither can be relabelled as chip cycles without validated timing inputs and a complete interrupt/callback model.
