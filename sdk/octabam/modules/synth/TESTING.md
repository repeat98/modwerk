### FOLLOW OFF on an FM SYNTH track (30 October 2026, the fix after the verifier's walk)

On the 4d25490 images (TEST1 / TEST6) an FM SYNTH track whose FOLLOW was OFF (the quantizer's per-track AUDIO SCALE OFF bit) only lost the ROOT transpose: its keys were still snapped (E PHRYGN, trig keys 1..16 one at a time gave 0x400 0x400 0xe00 0xe00 ... instead of SCALE OFF's 0x400 0x900 0xe00 ...). `poly.s` `po_start` read the scale mask through `SCALE_AT` without the track's bit, and `po_snap` snaps whenever that mask is non-zero. The author's `342c533` tests the bit where the mask is stored (`btst %d2,QZ_AUDIO_OFF_AT` after `jsr SCALE_AT`: set, T_SCALE := 0 for that track), so `po_snap`, the ROOT add and the same-scan key sweep all see SCALE OFF on that track while the other tracks keep the mask; 12 bytes of engine code, no project-format change. Emulator, TEST7: T1 FM SYNTH VOIC 4, CHROMATIC, E PHRYGN, each trig key alone: FOLLOW ON gives the TEST6 set (0x1800 0x1d00 0x1d00 0x2700 ...), AUDIO 1 FOLLOW OFF gives exactly SCALE OFF's words (0x400 0x900 0xe00 ... 0x4f00), FOLLOW ON again the set; a 2.21-saved project with `#SEQUENCER_AUDIO_SCALE_OFF` covering AUDIO 1 loaded on FM Synth alone (no rows): T1 plays plain semitones, T2 (FM SYNTH, not OFF) the PHRYGN set. The author's own remix of SYNTH MACHINE + SCALE QUANTIZER with `342c533` gives the same words.

### The slot GAIN fix (31 October 2026, the author's `bb784c4`)

The author's report (31 October 2026, MKI): an FM SYNTH track's level jumped when a sample was loaded into the FLEX slot the track is assigned to. Traced on the emulator with his own files (`guitar.wav` + `guitar.ot`, GAIN raw 72 = +12 dB): the loader reads the `.ot`'s GAIN into the slot's settings record (`0x100b14f0 + 0x448 * slot`, +0x10c raw, +0x10e linear from the table at `0x400b3164`, 2048 = 0 dB, 8153 = +12 dB); `0x40004f9c` publishes that linear value into the per-track word `0x80001850 + 2 * track` (at every load, CLEAR SLOT, ATTRIBUTES edit, project load and voice start); the frame builder's per-voice writer `0x40004bd4` copies the word into halfword 29 (+58) of the track's 64-byte DSP voice record (`0x80000110 + ping * 0x200 + 64 * track`, the ping being built, `0x800000e0`) every frame, and the DSP applies that halfword every frame. An FM SYNTH track is a FLEX-kind track with no sample, so it inherited its slot's GAIN: MAIN rms -31.3 -> -19.2 dBFS (+12.1 dB) within 400 ms of the load on the sounding note, through STOP / PLAY and on every later note (TEST8 and the pair image alike).

The fix is the author's `bb784c4` (`poly.s`, `sy_render`, the sample-free path `sy_call`): on every call for a chosen FM SYNTH track (`po_signed` = 1; not a sample track, not SY DRUM) halfword 29 of the track's voice record addressed by the build ping is written 2048 (0 dB), registers only, no stock site; `sy_render` runs after the stock writer and before the eDMA ship of that record, so the DSP always receives 0 dB for an FM SYNTH track and the engine's level law (`LEVEL`, `HEADROOM`, `T_GMAX`) owns the level. The slot's GAIN attribute is ignored on an FM SYNTH track entirely; a sample track keeps the stock writer's word, and a track that leaves FM SYNTH for FLEX takes its slot's gain again at once (the stock writer runs every frame). 42 bytes of engine code; the author's own remix of SYNTH MACHINE + SCALE QUANTIZER builds (`c411e6f3…`, was `3f5e00ee…`) and his `align_check` passes.

Image: TEST9 (above) is TEST8 plus this commit. Its MAIN OS differs from TEST8's in 165 ranges of the stock section, 192 bytes, every one of them a `jmp` / `jsr` / reference target into the appended DRAM runtime moved by 40 or 42 bytes (the poly unit grew by the fix; every symbol after `sy_call` and every unit linked after poly moved; `checks/classify_ranges.py`: 165 explained, 0 unexplained), and in the appended runtime itself (the fix and the moved code; `runtime.elf` 165,800 B, symbols after `sy_call` +42 within poly, +40 after it; `sy_nat` new). Nothing else: the branch head before the fix, rebased onto main `00ecaf52`, rebuilds TEST8 byte for byte (image `d2d250a6…`, upgrade file `f726d4e5…`, runtime `52c3d08a…`), so main's 30-31 October changes (#1029, #1094, #1095) change no byte of the card image.

### The chooser commit on the base (Jannik Aßfalg’s answer on #555)

The base owns the machine chooser’s commit (`0x4007981c`, which calls a machine’s `admit_track` and `assign`); the author’s machine-window hook `fm_main_commit` (`0x40079816`, 8 bytes) starts 6 bytes before it. - `assign` is his row choice and machine-change init (2.12): a track that becomes FM SYNTH is signed in the Part and its shadow and gets the FM init unless it plays FM already (`fm_choose`, `ml_reset`); a track that leaves it is unsigned with FLEX’s init at once, and `ui_tick` gives a stock machine other than FLEX its init once the commit has stored it (the record’s `assign` is not told which stock machine was picked).
