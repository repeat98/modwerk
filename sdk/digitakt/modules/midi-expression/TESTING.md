Version 0.13.0-experimental, Digitakt I OS 1.54 (stock file SHA-256 f78ba80f…3cf6), Core 2.1. Every result below names the version it was measured on.

## Evidence tier

`author-hardware` for 0.13.0: the author's v013 run on the unit (below). 0.12.4 was `author-hardware` too: the full `hwqual.py` run on the author's Digitakt, recorded in [evidence/hardware-testing.json](evidence/hardware-testing.json). 0.13.0 changes how the page opens, the factory defaults and when the power-on file is written; the MIDI and audio code is the same as 0.12.4's.

Emulator scripts take the image's settings from `toolchain/emu-NAME.env` (`scripts/emu-image.sh NAME` builds and sets one up): `set -a; . toolchain/emu-NAME.env; set +a; digiemu/.venv/bin/python scripts/SCRIPT.py`.

## Stock flows compared (0.13.0, emulator)

With and without the mod: SETTINGS keeps its rows and order, EXPRESSION is added below SYSTEM; TRK + trig, PLAY and STOP work with the page up as in SETTINGS; NO from the page returns to SETTINGS, and SETTINGS' own NO closes it as stock; SAVE PROJECT AS, LOAD PROJECT and CREATE NEW as stock (emu-store.py). With nothing switched on (the factory settings), a MIDI track's own sends pass untouched: the host tests check that a value nothing live is aimed at goes out as stock, and that a track gets its own values back once nothing is.

## Files and safety (0.11, unchanged since)

Each file is written whole to `/cfw/expression/_temp/…`, then whole in its place; files have a fixed size (padding after `END`), so a rewrite in place never leaves old bytes. A file is used only if it starts with its header and has an `END` line; otherwise its `_temp` copy, otherwise the defaults. The host tests feed 3,000 files of random bytes (some with a valid header and `END`): every value ends up in range every time. The firmware's file calls are used as Digi Slicer uses them, one file open at a time, from the UI tick, only while the filesystem's mutex is free. In the emulator a 5 KB file takes about 0.12 s to write, holding the UI (and, measured, the MIDI tracks' task) for that long. **0.13.0:** the power-on file is written only while the sequencer is stopped and nothing has been played for 2 seconds; project files are written while the firmware saves the project, presets when you save one.

## What the host tests cover (0.13.0)

Routing (auto channel, TRACK CHANNEL, CHAN off, audio tracks); sums within the MIDI limits for THRU and every route; release on a track change; merging of values on one CC number (MW with a CC VAL slot on SEL 1, BC with SEL 2, two slots on one SEL, SEL changed while merged); a fuzz of 300 rounds of 60 random events with every message valid and everything back to stock at the end; only the MIDI tracks' task sends, one wake queued at most, the buffer never filled past its room; unchanged values not sent again, changes and forced sends always; the track's own value from its parameters until it sends one; velocity sensitivity for audio and MIDI tracks, recorded velocity untouched, VEL as a source; the audio render's routes and TUNE; the MIDI LFO routes in and out of the LFO's words; the page: opened from the SETTINGS row, TRK + trig and the transport passed to stock, LEVEL kept from the menu, NO back to SETTINGS with its release kept, a page key closing it, the track box following the active track, the factory settings OFF; its keys, knobs, lists, FUNC jumps and drawing; the files: waits for the drive, current.txt a second after a change and only once nothing plays and the sequencer is stopped, saved and loaded by slot (a rename keeps them), defaults for a project without a file, power-on, a torn file (the _temp copy is read), both broken (the defaults), a hand-edited file (spacing, comments, CRLF, lower case, junk lines, out-of-range values, missing keys), presets saved, listed, loaded, RESET and DEFAULT (and a broken default preset: Factory), a failed write retried, every file closed, 3,000 random files; the preset menu: a 1-second push, SAVE with a name, LOAD with the LEVEL knob, RESET, DEFAULT, NO back, a short push opens nothing.

## On a unit

- **0.4–0.7, audio tracks** (internal sounds, by the author): bend, routes, the page and its knobs, velocity sensitivity, the LFO destinations of audio tracks.
- **0.8, MIDI tracks:** froze the unit. 0.8 sent MIDI itself from the MIDI input and UI tasks; on hardware that held everything back or let a second task into the DIN driver. 0.9 sends only through the MIDI tracks' own task.
- **0.9.0–0.9.2:** `hwping.py` showed each value once, as expected, after 0.9.1 stopped resending unchanged values. `hwstress.py` on 0.9.2: 25 of 25. Measured round trip through a USB MIDI interface: live notes 12 ms median, pitch bend 11 ms, CC 1 4 ms.
- **0.10–0.12.3, everything** (by the author, by hand): every feature on audio and MIDI tracks, over DIN MIDI and USB MIDI, sequencing several synths at once; saving and loading projects, power-on, presets, the MIDI LFO destinations, fine BEND.
- **0.12.4, `hwqual.py`** (by the author, DIN and USB at once, 7 November 2026): all eight MIDI tracks exact against the model, notes and V.SNS, 3,000 random messages, latency (0.9 ms USB, 2.9 ms DIN round trip), the sequencer over MIDI, live input with external clock, a 20 s flood of 15,511 messages with the sequencer playing (over USB), saving and CREATE NEW, the page by eye. Losses over DIN came from the interface (it drops a message just after a clock byte, `loopback.py`) and a loose cable, not the mod. The script's runs on 0.12.4 are timestamped in their logs from 19:56 on 6 November to 01:48 on 7 November; the author puts the time on the unit at about 8 hours over 0.10–0.12.4, his own playing included.
- **0.13.0, `hwqual.py --only v013`** (by the author, over USB, 7 November 2026, 11 of 11, 7.2 minutes; [summary](https://github.com/tekomelu/Digi-Expression/blob/d1d427a807d25c3b81e03d586ce42370eb58b7c1/results/hardware/qual-v013-20261107-134452/summary.md)): SETTINGS > EXPRESSION is the last row and opens the page of the active track; TRK + trig moves it (MID A, SMP 1); NO goes back to SETTINGS with the row selected and NO again closes SETTINGS; TRIG closes the page as stock; PLAY and STOP work with the page up. With MIDI track A reset to FACTORY, 8 notes went out and no pitch bend, aftertouch, mod wheel or breath (scripted); after reloading EXPR TEST it passed pitch bend again. A new project showed THRU OFF and BEND OFF. A change made while playing and the unit switched off without STOP was not kept; the same change after STOP and 5 s was.

## Measured resources

RAM (0.13.0, test images): alone, 93.3 KB of the module area stay free; with Digi Slicer, 1,168 bytes; with Digi Perform, 74.7 KB. No memory is allocated at run time. CPU: see the table; the audio render skips a track at once unless a source with a destination is live on it.
