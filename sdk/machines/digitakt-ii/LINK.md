# Digitakt II USB link

The DT2 OS 1.17 port starts with the Rytm's MWL SysEx wire and the Digitone II's
link and runtime work, not another protocol or loader. The native DT2 responder
and runtime glue are **not implemented**. The independent prerequisite below is
implemented; passing it does not qualify a firmware build or a device connection.

## Check the stock bindings before porting

With Node 24, from the repository root:

```powershell
node scripts/dt2-link-preflight.mjs --stock 'C:\private\Digitakt_II_OS1.17.syx'
node scripts/dt2-link-preflight.mjs --stock 'C:\private\Digitakt_II_OS1.17.syx' --base-ref origin/base/digitakt-ii-next
```

The command only reads files and local Git objects. It uses Modwerk's existing
ELE3 reader, accepts only the exact stock 1.17 SHA-256, and checks MAIN's identity.
It walks the high-speed configuration templates reached through the native USB
profile table, checks the MIDIStreaming interface and bulk endpoints 01/81 in
MIDI, Audio/MIDI and Overbridge, and refuses another interface using those MIDI
endpoints. Other interfaces and their alternate settings retain their ownership.
The template's zero total length is intentional: stock fills it at runtime.
Full-speed fallback and host driver exposure are not qualified by this check.

It verifies the router candidate and transmit-path hashes in
[`usb-link-bindings.json`](usb-link-bindings.json), then checks their ranges
against the base's core, common, add and dev patch sites. This is a conservative
union including optional additions, not a replacement for the builder's variant
selection or all-site preimage checks. The default reads working-tree recipes;
`--base-ref` reads a single resolved local commit, including its provenance-guarded
core recipe copy. Fetch the cumulative branch first when checking current work.
Duplicate copy destinations are refused: the builder stages copies in order,
so an ambiguous recipe must not be audited by choosing its first core match.

Exit 0 means **offline binding checks passed**. Exit 1 means a mismatch or
unsupported recipe needs investigation. JSON output contains addresses, hashes,
endpoint ownership and explicit unresolved gates; it never contains stock bytes.
Tests use invented USB descriptors, not firmware fixtures:

```sh
npx vitest run scripts/dt2-link-preflight.test.mjs
```

## Verification, 26 November 2026

On Node 24.22.3, the owner's stock file passed against working-tree recipes
based on main `4d4af12f2c035387db711ac555e77794e1f2b4e6` (22 sites) and cumulative
DT2 base `de972bf0ca8c08c6270bc0c94a8099a57eaf411e` (47 sites). Both checks found
the three MIDI interfaces and no guarded-range overlap. The 12 new tests and
11 existing ELE3/shared link-wire tests passed, as did ESLint and the machine
base Python suite (29 passed, three Model:Cycles C fixtures skipped because no
host C compiler was available). No firmware build, emulator or unit test ran.

DN2 runtime source was inspected at PR #1842 head
`4bb7a2897bac83f7fc44c05e7e62efe04691b1cf`; it is an open contribution by
prodbysmolec, not a merged or DT2-qualified implementation. The DT2 port's
ownership and transmit bound have been raised on the board with its holder.

## What must be settled before a native port

The [26 November bounded-transmit investigation](../../../docs/verification/2026-11-26-digitakt-ii-bounded-transmit.md)
traces the additional descriptor-allocation wait, the conditional try-allocate
path and reset ownership. It identifies a DN2-shaped router site and a guarded
native integration candidate; neither is implemented or hardware-qualified.

- **Shared ownership:** the DN2 link task held by prodbysmolec explicitly includes
  sharing with DT2. Coordinate the DT2 adapter boundary there. Claptom's Mixer,
  machine and sequencer work stays on the DT2 cumulative base draft #1999.
- **Bounded transmission:** DT2's stock SysEx sender reaches queue-space waits
  in the USB MIDI serializer. The outer sender's abort pointer does not bound
  those inner waits. DN2 PR #1842 still calls its stock sender from the UI tick.
  That design alone is not proof of bounded DT2 sending. A disconnected or
  non-reading host must not stall the UI or sequencer. Stop if a safe adapter
  requires taking over stock's driver or an unprotected check-then-send race.
- **Identity and diagnostics:** use the source/layout identity generated by
  `machine-base.py`, unit-chosen bounded reads and the shared log layout. No
  arbitrary memory reads or fabricated upload capability.
- **Loading:** reuse `sdk/runtime/upload` and `sdk/runtime/loader`. Establish
  DT2's stopped state, uncached alias and cache operations, every paused task,
  patchable range and exclusive pool/staging ownership. DN2 addresses and its
  reported hardware results are not DT2 bindings or evidence.
- **Hardware:** qualify the exact resulting build, stock MIDI traffic and
  audio/Overbridge coexistence in all three modes, including disconnect and
  transmit backpressure. No such DT2 link test has been performed here.

## Provenance

Bindings were independently checked against the owner's exact stock OS 1.17
through Modwerk's reader on 26 November 2026, recovering the static findings
from the 16 November investigation. Only addresses, hashes and USB interface
facts are recorded. No DigiKit source, loader, dispatcher, binary component or
mechanical translation is used. These facts do not establish an original
implementation of the native USB driver. Stock firmware remains private.
