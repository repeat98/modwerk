# comp-preview

Port of rytm-mods-src `mods/0006-comp-preview` (MrScruff; hardware-verified there). Full usage: rytm-mods-src
`docs/MANUAL.md`, section 0006.

On the FX track, press AMP (the compressor page) again for a preview page: a scrolling estimate of the master compressor's gain reduction, computed from the voices, the PRE delay and reverb returns, master distortion and the compressor settings. FUNC + AMP switches layout (full or GR alone), FUNC + LEFT/RIGHT the scroll speed, FUNC + UP/DOWN the vertical scale.

## Sites

3 sites (1.0 had 6), the claims rytm-mods' registry makes for its default build
(`registry/allocations.toml`, owner `0006-comp-preview`), less the set-page slot core-ar2 0.4 now
handles for every view:

| addr | op | |
|---|---|---|
| 0x401213a0 | jmp | `jmp comp_preview_comp_probe` |
| 0x401e11b0 | ptr | pointer -> `comp_preview_comp_keys` |
| 0x401e11b8 | ptr | pointer -> `comp_preview_comp_draw` |

A detour is a `jmp` site over the whole stock instructions it displaces; the stub re-emits them
as in rytm-mods. Where rytm-mods patched the address operand of a `jsr`/`lea`/`move.l #`, the
site is elemod's `keep2` (the opcode word kept, the address the mod's). A pointer in a data
table is a `ptr` site.

From 1.1 the preview is listed in the COMP view through core-ar2 0.4's `core_view_pages`
(`comp_preview_view_page`: stock page 11 again, order 20), in place of 1.0's own list for the
view.

## Changes from rytm-mods

### 1.1: the COMP view's list through core-ar2 0.4

1.0 replaced the COMP view's page list with its own (page 11 twice), so no other mod could add a
page behind the COMP key: duck, which adds DUCK there, was refused beside it. Core-ar2 0.4 builds
each page key's list from stock's pages and the pages mods add. comp-preview now adds its entry
there, and its draw and key hooks tell the preview apart by its page (11 again, past the
first entry) rather than by "any entry past the first", so a page another mod adds after it is
left alone. With duck the COMP key steps COMP, preview, DUCK. The preview itself is unchanged, but for one guard: its estimate in the audio interrupt stands
aside while core-ar2 0.4's `core_audio_load` says the last block was over 95% busy, and comes
back below 88%, so the trace pauses rather than the audio or the UI running short. Stock alone
peaks near 84% on a unit; the estimate costs 4 to 5 points.
Needs core-ar2 0.4 (OS 1.74 only); 1.0 does not link with core 0.4.

The COMP view keeps the page it was on when you come back to it, so the preview is not dropped.
1.0 did this with its own hook on the COMP view's set-page slot; core-ar2 0.4 now does it for every
view, so DUCK and any other added page are kept too, with or without comp-preview.


- Generated by `tools/port_mod.py`. The code is unchanged; each label a site names gets a
  `.globl` alias carrying the mod id on the line before it, and the stub keeps using its own
  local labels.
- rytm-mods' default build params are fixed with `.equ` (`P_...`), as its build passed them;
  claims and code its diagnostic params select are left out.
- Every section the stub had in separate caves is `.text` here, one `.run` the linker places in
  the DDR mods area.
- The detour at 0x401213a0 lands across `lea 0x8000e508,%a1`, which the stub re-emits before rejoining at 0x401213aa: the site takes that instruction whole (10 bytes) and nops its tail.
- `calib.inc` (rytm-mods' generated calibration tables) is copied beside the source.

## Test (on a unit)

1. FX track, AMP, AMP: the preview page.
2. Play a pattern and lower THR: the gain-reduction line dips below the dotted threshold row. FUNC + AMP, FUNC + arrows change layout, speed and scale.
3. Turn SEQ: its value (e.g. LPF) shows, then the label goes back to SEQ after about 1 s.

## Results so far

### 1.1 on core-ar2 0.4

- rytm-emu, OS 1.74: without duck, FX then AMP through COMP and the preview, 9 screens
  pixel-identical to 1.0 on core 0.4. With duck: COMP, preview, DUCK, COMP, preview, DUCK; DUCK's
  knobs turn.
- Hardware, Analog Rytm MKII OS 1.74, 2026-10-21, core-ar2 0.4: in the full build (Q4A4) COMP and the preview cycle, the preview's FUNC keys work and it is kept on leaving the FX track; with duck (Q4D4) COMP, preview, DUCK cycle and the preview's trace runs while DUCK ducks. With cpu-probe in the build (Q4D4, and Q4F4 without duck), CPU read 100% now and then and the preview's trace stopped, coming back by itself. Then with the load guard (U4A4, U4D4, U4F4, U4M4): the preview is kept on the COMP view with and without duck; in the busiest case (DAC SUM, fx-sends' chorus and the preview) CPU still touches 100%, the audio interrupt reads 92% and peaks at 94%, the trace stops now and then and comes back by itself, knobs and values keep responding meanwhile, and nothing is audible. The guard rarely engages at these loads.

- Built with elekloader at d17478b and m68k-linux-gnu binutils 2.42: `.run` 3856 B,
  6 sites, 19 relocations; lint OK; links with core-ar2 0.1 and the other ports.
- Against rytm-mods-src's default build (all of its mods at their default params; "T2" below): the original stub, re-assembled
  as rytm-mods' build does, equals T2's caves byte for byte (.text 0x40029060, .state 0x402cdf94, .aux 0x402ccfa8, .tab 0x4002871c, .ui 0x400287fc, .sat 0x401ba290, .ring 0x40289ab8, .sc 0x40289b38). Each of its 61
  labels was then disassembled in T2 and in the full build with every address named by its label: the
  instructions match (two tables, `reltab` and `hrestab`, compared as bytes: identical).
- Every byte the full build changes in the OS is inside one of the ports' sites, every one of these sites is
  patched in T2 too, and the `bytes` sites write exactly T2's bytes.
- rytm-emu (3c4c42c), the full build (core-ar2 with all eleven ports): FX track, AMP twice, PLAY: the estimate scrolls, pixel-identical to T2 except one label: here the SEQ knob's value text (LPF) goes back to SEQ after about 1 s, in T2 it stays LPF. The label times itself on DMA timer 0's counter. In the emulator nothing starts that timer before the OS, so without a core it reads 0 and the value never times out; core-ar2 starts it when it finds it stopped (`mods/core/core.s`). On a unit something before the OS has already started it, so both builds should time out as here: step 3 of the test checks that.
- Hardware: on an Analog Rytm MKII, 2026-10-14, in the full build (core-ar2 with all eleven ports): works as described; the SEQ value goes back to its name after about 1 s, as the emulator
  showed with core-ar2.
