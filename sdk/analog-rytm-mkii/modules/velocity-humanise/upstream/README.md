# velocity-humanise

Port of rytm-mods-src `mods/0003-velocity-humanise` (MrScruff; `built` in its mod.toml, listed as verified on hardware in its MANUAL there). Full usage: rytm-mods-src
`docs/MANUAL.md`, section 0003.

On the TRIG page, hold FUNC and turn VEL: the label reads RND and the knob selects an amount N from 0, 1, 2, 3, 4, 6, 8, 10, 12, 16, 20, 24, 32, 40, 48, 64. Every trig on the track then plays at its velocity plus a random -N..+N, kept within 1..127. Release FUNC and VEL behaves as stock. Per track, kept with the pattern in core-ar2 0.2's mod storage (needs core 0.2; since 1.1 it no longer needs euclid-accents).

## Sites

5 sites (OS 1.73 addresses; 1.74's are in mod.json `ports`), the claims rytm-mods' registry makes for its default build
(`registry/allocations.toml`, owner `0003-velocity-humanise`):

| addr | op | |
|---|---|---|
| 0x400378ae | jmp | `jmp velocity_humanise_vel_amount_gate` |
| 0x4009afa0 | jmp | `jmp velocity_humanise_vel_humanise` |
| 0x400a85e8 | jmp | `jmp velocity_humanise_vel_text_gate` |
| 0x400a8f98 | jmp | `jmp velocity_humanise_vel_label_gate` |
| 0x400a87b6 | keep2 | the instruction's address operand -> `velocity_humanise_vel_get_ui` (stock `4eb9400bfd20`) |

A detour is a `jmp` site over the whole stock instructions it displaces; the stub re-emits them
as in rytm-mods. Where rytm-mods patched the address operand of a `jsr`/`lea`/`move.l #`, the
site is elemod's `keep2` (the opcode word kept, the address the mod's). A pointer in a data
table is a `ptr` site.

## Changes from rytm-mods

### 1.1: the amount in core-ar2 0.2's mod storage, and no euclid-accents

In rytm-mods (and 1.0 here) the amount index was bits 2..5 of the track's euclid-enable byte (live
TrackPattern +0x2ca). Only euclid-accents' sites kept those bits safe (its masked getter, bit-keeping
setter and trig_fire mask) and saved them (its pattern track save/load hooks), hence the `requires`.

1.1 keeps the index in a core storage field (mod.json `"storage": [{"sym": "vel_rnd", "scope":
"track", "bits": 4}]`, `"resources": {"core": "0.2"}`), item the live pattern, index the track:

- `vel_humanise` (in trig_fire) reads `core_store_get(vel_rnd, a2, (a3 - a2) / 917)`: a2 is the live
  pattern trig_fire plays, a3 the track base;
- FUNC + VEL (`vel_amount_gate`) and the dial (`vel_get_ui`) get the live track from the accessor as before,
  map it to (live pattern, track) with `track_item` (`../shared/live-track.s`, range and stride checked),
  then get, add and clamp 0..15, and set; the change notification is still raised, so the pattern counts as
  changed;
- `"requires"` is just `core`: the mod works alone, and the euclid-enable byte is no longer touched;
- projects saved with 1.0 load with every amount at 0 (their amounts are in stored byte +0x279 bits 3..6,
  which nothing reads now).

### 1.0

- Generated by `tools/port_mod.py`. The code is unchanged; each label a site names gets a
  `.globl` alias carrying the mod id on the line before it, and the stub keeps using its own
  local labels.
- rytm-mods' default build params are fixed with `.equ` (`P_...`), as its build passed them;
  claims and code its diagnostic params select are left out.
- Every section the stub had in separate caves is `.text` here, one `.run` the linker places in
  the DDR mods area.
- 0000-shared's runtime is assembled into the mod, at the end of the unit (`../shared/shared.s`): its references into it, absolute in rytm-mods, are PC-relative here, so the code is a few bytes shorter.

## Test (on a unit)

1. TRIG page, hold FUNC, turn VEL: the label reads RND, the popup 0..64.
2. N = 32, play a track of equal-velocity trigs: the hits vary in level. N = 0: all equal.
3. Save, power-cycle, reload: N is kept.
4. Without euclid-accents in the build: 1..3 the same, and euclid on/off unaffected by N.

## Results so far

### 1.1 on core-ar2 0.3

- Needs core-ar2 0.3 (`resources.core`), which saves track and pattern fields on stock's per-part
  saves; with 0.2 the field was lost at a power-off without a project save (below). Core 0.3 is
  OS 1.74 only, so 1.1 builds for 1.74 only; the 1.73 source stays the porting master.
- Hardware, Analog Rytm MKII OS 1.74, 2026-10-20, core 0.3 with all eleven mods (C3A4): test steps 1 to 3 pass, N kept through a power-cycle without SAVE PROJECT; step 4 passes on the same build without euclid-accents (C3N4).

### 1.1 (core-ar2 0.2)

- Built with elekloader (core-ar2 0.2) for OS 1.73 and 1.74: `.run` 828 B, 5 sites, 8 relocations, imports
  `core_store_get`, `core_store_set`, `vel_rnd`; lint OK with core 0.2 alone and with euclid-accents 1.1.
- rytm-emu, core 0.2 + euclid-accents 1.1 + velocity-humanise 1.1, OS 1.73 and 1.74 (same results on both):
  TRIG page, FUNC + VEL on track SD of A01: the dial reads the amount back (2, then 64 at index 15), the
  field sits at live pattern 1, track 1 and nowhere else, the euclid-enable byte stays 0/1. On A02, track CB:
  index 8 (N = 12) at live pattern 2, track 11. Playing (a build with counters added to the stub, not
  shipped): only SD's trigs were randomised, index 15, velocities 30..127.
- Persistence, core-ar2 0.2 (emulator): stock saves an edited track into the stored project through
  `pattern_track_save`'s second caller (0x400bf7ac, once per edit and per track on a pattern change), which
  core does not hook, so the field is not in the stored project's tagged store after an edit or a pattern
  change, and a power cycle (which keeps the stored project) brings it back as 0, while the stock fields of
  the same track are kept. A project save (SETTINGS > PROJECT > SAVE PROJECT AS) runs the whole-pattern
  serializer, which core does hook. Fixed in core-ar2 0.3.

### 1.0

- Built with elekloader at d17478b and m68k-linux-gnu binutils 2.42: `.run` 656 B,
  5 sites, 0 relocations; lint OK; links with core-ar2 0.1 and the other ports.
- Against rytm-mods-src's default build (all of its mods at their default params; "T2" below): the original stub, re-assembled
  as rytm-mods' build does, equals T2's caves byte for byte (.text 0x402cdddc). Each of its 9
  labels was then disassembled in T2 and in the full build with every address named by its label: the
  instructions match.
- Every byte the full build changes in the OS is inside one of the ports' sites, every one of these sites is
  patched in T2 too, and the `bytes` sites write exactly T2's bytes.
- rytm-emu (3c4c42c), the full build (core-ar2 with all eleven ports): TRIG page, FUNC + VEL: all 16 screens pixel-identical to T2 (stock differs on 13).
- Hardware: on an Analog Rytm MKII, 2026-10-14, in the full build (core-ar2 with all eleven ports): FUNC + VEL shows RND and the sixteen
  amounts, hits vary with N and not at 0, per track, euclid unaffected by the stored amount, and
  the amount kept through save, power cycle and reload. TRK + FUNC + VEL stays on the selected
  track.
